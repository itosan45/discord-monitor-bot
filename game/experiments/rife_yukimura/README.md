- 元: `assets/sprites/真田幸村_歩き_6コマ.png`(256×256×6、純マゼンタ背景)。**元の絵は変更していない**。
- 結果: `真田幸村_歩き_12コマ_RIFE実験_v1.png`(3072×256、偶数番=元の絵、奇数番=RIFEの補間コマ。最後→最初も補間して循環)。**ゲームには組み込んでいない**(実験のみ)。
- 比較動画: `compare_yuki_walk.mp4`(左=元6コマ10fps、中=単純クロスフェード12コマ、右=RIFE 12コマ20fps)。`legs_orig_vs_rife.png`は脚の拡大(上段=元、下段=補間)。

- 未確認: ゲーム内での動き・接地位置・当たり判定との相性、他キャラ・攻撃コマ。

## 追記: 足の入れ替わりが急に速くなる問題(オーナー指摘、2026-10-14)
- 原因は元の6コマの作り。コマ間の脚の動き(RIFEのフロー測定)は 4.8 / 2.9 / 5.7 / 7.1 / **10.4** / 5.9 px と偏っていて、コマ4→5(脚が交差する所)だけ約3.6倍大きい。足の間隔でも 63→78→74→56→80→**40** と、80→40が1コマで起きる。補間で枚数を倍にしても偏りは残る(等間隔の12コマは足の間隔の最大変化が1コマあたり21px)。
- 対策: 各組を細かく補間して脚の経路長を測り、**経路長が等間隔になる位置で12コマ(16コマ版も)を取り直した**(`retime2.py`)。足の間隔の最大変化は1コマあたり16pxに下がった(元は1コマ40px=12コマ相当で20px)。
- 比較動画 `compare_yuki_walk_等速化.mp4`: A=元6コマ(10fps)、B=等間隔に補間した12コマ(20fps)、C=等速化した12コマ(20fps)。
- 限界(未解決): 足が交差する最小の間隔(40px)の前後は、まだ1コマ10〜16pxで他より速い。元の絵そのものが「交差ポーズ」に急に入る作りのため。完全な等速には、画像担当に歩きを描き直してもらう(交差の途中のポーズを足す)方が確実。
- 未確認: ゲームの歩く速さ・接地足の滑り・当たり判定との相性。測定は画像上の近似で、感覚と一致するかは動画で要確認。
