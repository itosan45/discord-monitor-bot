# 関ヶ原乱舞 引き継ぎ書(Codex向け)

## 1. 概要
- 戦国ベルトスクロールアクション「関ヶ原乱舞」。IFストーリー(関ヶ原に真田幸村が参戦)。
- 公開先: https://sekigahara-ranbu.vercel.app (Vercel プロジェクト `sekigahara-ranbu`)
- リポジトリ: `itosan45/discord-monitor-bot`、作業ブランチ `ccr-851ab851-t271uq`(PR #3)
- 主な遊び方: Android の Chrome(横画面・タッチ操作)。友人にも共有されている。
- オーナーへの連絡・報告はすべて **日本語** で(英語表記は読めないと言われている)。

## 2. フォルダ構成
| 場所 | 中身 |
|---|---|
| `index.html` | **完成品**(自動生成。直接編集しない) |
| `gfx/` | 完成品が読む画像・音楽(`atlas_*.webp`=キャラ絵、`bg_*.webp`=背景、`bgm_thunder.mp3`=第一幕BGM) |
| `game/game_src.html` | **ゲーム本体のソース**(JavaScript 1ファイル、約2000行)。直すのは基本ここ |
| `game/build.py` | ソース+データ → `index.html` を組み立てる |
| `game/data/audio.json` | 効果音・声・BGM(base64)。声の追加時は対応する音声取込設定も更新 |
| `game/sprites/` | キャラ絵の変換スクリプトと位置データ(sprmeta.json, hands.json) |
| `game/tests/` | ブラウザ自動テスト(Playwright) |
| `assets/sprites/` | 元絵(Codexが追加している連番シート。ファイル名 `<武将名>_<動作>_<N>コマ_v*.png`) |
| `vercel.json` | 公開時は index.html・manifest・gfx をそのまま配信するだけ |

## 4. キャラ絵(スプライト)の更新手順
新しい元絵を `assets/sprites/` に入れたら:
```bash
cd game/sprites
python3 mk.py yuki            # 武将を指定して再生成(指定なしで全員。既存データには足し込み)
python3 mku.py                # 手ぶら版(<武将>_u)を作る ※mk.py の後に必ず
python3 hand.py               # 手の位置(武器を持たせる位置)を再計算 ※最後に必ず
cd .. && python3 build.py     # sprites/atlas_*.webp を gfx/ にコピーして組み立て
node tests/tmeta.js           # 位置データ欠けがないか必ず確認
```
- 元絵の選び方: ファイル名の末尾 `_v3` > `追加v1` > … の順で新しいものを優先(mk.py の `find()`)。
- 新しい元絵は大きさがばらばらに届くことが多い。組み込むたびに、待機の絵と並べて背の高さを確認し、ずれていれば mk.py の `KFIX` で補正すること(例: ボスの歩き8コマv2は1.2〜1.6倍大きく描かれていた)
- 大きさの補正は mk.py の `KFIX`、他のコマの絵が混ざった時の消しゴムは `CUTS`、色の補正は `DEMAG`。
- 隣のコマの破片は `descrap()` が自動で消す。
- **注意**: 以前 mk.py が sprmeta.json を丸ごと上書きして、馬・騎馬兵・アイテムが消える事故があった。現在は足し込み式に修正済み。build.py も位置データ欠けがあれば止まる。

## 5. ゲームの仕組み(game_src.html の主な場所)
- 状態管理: `G`(全体)、`TY`(キャラ・敵の能力表)、`WPN`(拾える武器)、`STG`(ステージ)、`DIFF`(難易度 やさしい/ふつう/むずかしい)
- 進行: `stepGame()` が1フレーム処理、`frame()` が描画ループ(低スペック端末は `setLowRes` で軽量化)
- プレイヤー: `updPlayer`、攻撃開始 `startPAtk`、溜め攻撃 `CHG`/`startCharge`、必殺 `startSpecial`、奥義 `startUlt`
- 敵: `updEnemy`、`spawnEn`、ボス技 `bossTech`
- 被弾: `hurt()`、ガード、`knock()`
- 相方: `partnerCtl`、かばう `tryCover`、殿(しんがり)`rearCheck`/`rearStep`
- 描画: `drawSprite`(キャラ絵)、武器を持った時は手ぶら版に切替(`UMAP`、全武将。足りない動きは `UGEN` の代用表で補う)。鎖鎌の長押し回転・貫通投げ・引き寄せは `kusariCtl`
- 画面: タイトル `drawTitle`、キャラ選択 `drawSelect`、チュートリアル `HT_STEPS`、一時停止メニュー `PZM`、ストーリー `SCN`
- 主人公6人は `sc:1.08`(足軽より少し大きく見せるため)
- ジャンプ力: `p.vz=T.jump*1.2`(TY 各武将の `jump` 値 × 1.2)
- 溜め攻撃(長押し→離す)は武器ごとに変わる: `chargeKind()` で判定。刀(景勝・信長・武蔵の持ち武器/長剣/妖刀)=居合 `startIai`/`iaiStep`/`drawIai`、槍=突進(従来の `startCharge`)、薙刀=回転斬り、斧・棍棒=地割れ、鉄砲=溜め撃ち、弓=三本矢、鉄扇=疾風、軍配=号令(`startCk`/`chargeStep`)。鎖鎌だけは `kusariCtl` で別処理。鎖鎌の絵(`drawSprite` 冒頭の `kart`): 普通の攻撃=`kslash`(鎌斬撃)、長押し=`kspin`(歩くと `kwalk`、現在は幸村・景勝・武蔵・信長・信玄)、投げ=`kthrow`、引き寄せ=`kpull`、空振りの巻き戻し=`kret`。元絵は `<武将>_鎖鎌_<動作>_<N>コマ`。大きさは mk.py の KFIX で武将ごとに補正済み
- ボスAI(`updEnemy` の `T.ai==='boss'`): 体力は定義値×1.25。プレイヤーの攻撃を読んでガード(`BGUARD`、防いだら反撃)や飛び退き(`BSTEP`)、技のあと連続技(`comboN`、怒り状態で最大2回)、6連続で殴られると振り払い(`BSHAKE`)。最上義光は `ai2:'archer'` で距離を取り、三本矢(`arrows3`)と矢の雨を使う。テストは `tests/tbossai.js`
- 音声(Gemini生成、`assets/voice/gemini/` に元WAVと manifest.csv): 名乗り=キャラ選択で再生(`AU.intro`)、必殺の掛け声=必殺技・奥義の発動時(`AU.spv`)、気合い=攻撃時(`AU.kiai`)、勝ちどき=ステージクリア(`AU.kachi`、import_voice.py で声の高さだけ変えた30人分(元の0.62〜1.45倍に均等に散らす)をほぼ同時(ずれ30ms以内)に重ねた1本を作って再生。再生速度でずらすとやまびこになるので注意)、殿=相方の殿(`AU.shingari`)。やられ声(Gemini)は不採用。雑魚の断末魔(`audio.json` の dv.foot、効果音ラボ素材)はしゃべっている3本(元の5番・6番・11番)をオーナー指示で削除し9本。差し替えは WAV を置き換えて `python3 game/tools/import_voice.py` → `cd game && python3 build.py`
- ユーザー録音の掛け声は `assets/voice/user/*.m4a` を原本として保持し、`game/data/audio.json` の `uv` にモノラルMP3で格納する。対応は `charge`=溜め攻撃、`hey`=ハッ、`seiya`=セイヤ、`victory`=ボス撃破後の大将号令(`AU.kc('call')`)。音声はコンプレッサー・音量調整・短いリバーブ・リミッターを通す。兵士の勝ちどき(`AU.kachi`)は従来音声のまま。
- 主人公の歩行テンポは `p.wp` の増分で制御。待機は `drawSprite` の `idle` 姿勢で腰を低くし、武器を前に構える。歩きは上下動と胴体の揺れを抑えた。
- 勝鬨の演出(ボス撃破後 `G.state==='bossdown'`): kt=60 で `kgunInit()` が味方の足軽10人(刀・槍の敵足軽の絵を流用)を画面の両端から呼び、主人公の周りに集める(`kgunStep`/`drawKgun`、描画は `renderWorld` の奥行き並べに混ぜている)。「えい!」(kt=180/214)と「おー!」(kt=250)で跳ねて刀を振り上げる(刀足軽は攻撃2コマ目、槍足軽は待機絵を傾ける)。足軽は主人公の奥側に並ぶ。主人公6人は kt=170 から `勝鬨_4コマ`(sprmeta の `kachi`、mk.py の KFIX で待機と同じ背丈に補正済み)を再生し拳を突き上げる(`drawSprite` 内、拾った武器は隠れる)。真田幸村の時だけ `redS()` で青い着物を赤に塗り替え(赤備え)、背中に六文銭の旗を手描き。声は30人分の勝ちどき1本だけ(前の掛け声・太鼓を重ねた版はオーナーの判断で不採用)
- 騎乗: 乗り手は立ち絵を腰で切って鞍に乗せる(`drawRiderPlayer`)。脚の長い絵は `MRIDE` で切り位置・高さ・大きさを補正(現在は武蔵のみ)。乗り手のいない馬(走り去る馬・奪える馬)は `mount_blue` の絵を使用。手描きの馬 `drawHorse` は絵の読み込み失敗時の予備のみ
- 会心(クリティカル): `hurt()` 内で判定(通常7%、溜め攻撃・居合30%、ダメージ1.6倍、「会心!」表示)。会心で倒すと `decap()` で首が飛ぶ(流血オフ `G.blood=false` なら笠・兜だけ)。頭の範囲は `headRect()` が絵の上部から自動で探す。ボス・騎馬は対象外
- 必殺ゲージ: 必殺技・奥義のダメージでは増えない(`hurt()` 内)。被弾でも増える(ダメージ×0.8)
- 注意: ゲーム内時計 `G.t` は `frame()` で進む。テストで `stepGame()` だけ回すときは `G.t++` も自分で進めること

### 対応済み(このセッション)
1. **馬上攻撃の画像が大きすぎる問題**: 実際に読み込まれていた大きい画像は宮本武蔵の `mountfull3_musashi`(2880×4160=展開48MB)だけだった。幸村らの `mountatk2_*`・`mountatk_*` は build.py が読み込み対象から外すので、実機では読まれない(ファイルは gfx/ に残るだけ)。武蔵の画像は `game/tools/trim_pack_atlas.py` で各コマの余白を詰めて詰め直し、新キー `mountfull4_musashi`(2048×2062=展開17MB、4096以内)にした。描画結果は元と1ピクセルも違わない(50コマ全部を比較して差0)。元の `mountfull3_musashi` は保持し、build.py が mountfull4 があれば mountfull3 を読み込まない。**他の5人に馬上の全身攻撃絵(mountfull3_*)が届いた時も、同じツールで `mountfull3_<名>` → `mountfull4_<名>` に詰めてから組み込む**(使い方はツール先頭)。ゲームは `mountfull4_ || mountfull3_` の順で読む。
2. **tnpcscreen**: ボスが被弾した時の押し戻し(`hurt()` の `t.x+=dir*d.kb*0.15`)が画面内への制限の後で効いていたため、右端で0.9px はみ出していた。押し戻しの直後に `keepFighterOnScreen` を呼ぶようにした。
3. **tmountedattack / theromatrix**: テストが build で外される `mountatk2_*` を期待していて落ちていた。実際に使われる `mountfull4_`(武蔵)/`mountbody3_`(他5人)に合わせた。詰め直しでコマの位置が行ごとに揃わなくなったので、theromatrix の判定は「その武器の5コマのどれかと位置一致」に変更。
4. **一体デバッグ(?preview=walk&hero=…)**: 信長・信玄・武蔵を指定しても武蔵になっていた(`SEL_ORDER` に3人しかなかった)。`HIDDEN` も含めて判定するようにした。6人とも確認済み。
5. **テストのWindows前提**: 全テストで環境変数が使える。`CHROME_BIN`(ブラウザ)、`GAME_URL`(遊ぶURL、既定は 127.0.0.1:8876。引数でも指定可)、`QA_OUT`(検査画像の保存先、既定は従来のWindowsのパス)。Linuxでは `QA_OUT=/tmp/...` を付ければリポジトリ内に「C:」フォルダはできない。

6. **石田三成が小さすぎる(オーナー指摘「子供みたいに小さい」)**: 待機以外の動きの元絵が小さく、胴の列の頭頂の高さで歩き約15%・攻撃/被弾約10〜15%、待機も約4%小さかった。元絵は変えず、game_src.html の `HFIX`(読み込み時に足元中心で拡大。手の位置 hands.json も同倍率)で他の5人の中央値にそろえた(最低1.05倍、最大1.2倍)。6人を並べた実描画で、待機・歩き・攻撃・被弾・長剣所持・槍所持を確認済み。新しい元絵が来て背丈を直したら HFIX の値も見直すこと。
   - 補足: `tpickupwalkweapons.js` は「武器を持って歩く専用絵 walkbody3_<武将>」がある武蔵・信長・信玄用。幸村・景勝・三成で実行すると元々失敗する(今回の変更とは無関係)。

7. **鎖鎌の分銅が浮いて見える(オーナー指摘)**: 元絵で分銅が体の後ろを回るコマは鎖が体に隠れて描かれておらず、分銅だけ宙に浮いて見えた。6人×鎖鎌6動作を全コマ目視し、浮いているのは 景勝 kwalk3・kwalk7、三成 kwalk4・kwalk5・kret4、信玄 kwalk4、武蔵 kwalk4 の7コマ(幸村 kret4 は左手から垂れていて自然なので対象外)。元絵は変えず、game_src.html の `KCHAIN`/`drawKChain` で該当コマだけ手元から分銅まで鎖を描き足す(体の後ろの鎖は体より先に描くので、体の外に出た部分だけ見える。三成 kret4 は分銅が胸の前なので体の上に描く)。座標は元絵のコマ内ピクセル。**新しい鎖鎌の元絵が来たら、同じように全コマを拡大して確認し、KCHAIN を見直すこと**(自動判定は鎖が薄い色だと見分けられず使えなかった。`game/tools/find_floating_kusari.py` は参考用)。

9. **キャラ画像のステージ別読み込み(Android のメモリ対策)**: 以前は起動時に全画像(展開後約245MB)を読んでいた。今は画面・ステージ・操作キャラ・相方から必要な組だけ読み、要らない画像は捨てる(`sprTarget`/`syncSprWant`/`sprRequest`/`sprRelease`、game_src.html)。常に読む: 敵兵・アイテム・味方足軽・乗り手なしの馬・家康(タイトルの影)。選択画面: 6人の本体。ステージ中: そのステージのボス+操作キャラと相方の一式(`heroBundle`: 本体・手ぶら・持ち歩き・馬上・幸村の槍投げ)。結果: 起動直後 約57MB、ステージ中 約103〜132MB。見た目は同じ画像のまま。

10. **重さの改善(オーナー指摘「倒した敵を引きずる」「雑魚が多いと重い」「相方が必殺を使いすぎ」)**:
   - **死体がカメラについて回る不具合**: 画面内にとどめる処理が死体にもかかり、カメラが進むと死体が画面端に押されて消えるまでついて来ていた(2か所: `updWorld` の keepFighterOnScreen と `updEnemy` 冒頭の clamp)。死体・瀕死は対象外にし、画面外に出た死体はすぐ片付ける。
